# ターミナル UI

`veritas` を引数なしで実行すると、ターミナルで操作する画面が開きます。コマンドを入力しなくても、結果の確認、仕様のレビュー、実行、テストの改善、設定の編集ができます。

```bash
npm install -g @under18dev/veritas
cd your-project
veritas
```

開くのは、カレントディレクトリのプロジェクトです。

## 開く条件

次の条件をすべて満たしたときだけ開きます。

- `veritas` を引数なしで実行した（コマンドも、`-C` や `--json` などのオプションも付けていない）。
- stdin と stdout が、どちらも対話的なターミナルである。
- 環境変数 `CI` が設定されていない（または `false` か `0`）。

それ以外のときは、これまでどおり help を stderr に出し、終了コード `2` で終わります。引数なしで `veritas` を呼んでいるスクリプトやパイプラインには影響しません。

## 画面の構成とキー

上部にプロジェクト名と最新の run（色付きのラベルで示す verdict、終了コード、開始時刻）、左にメニュー、右に選んだ画面、下部にその場で使えるキーが表示されます。下部のキーは表示している内容に合わせて変わるので、いま押せるキーがいつでも分かります。キー操作を受け付けているパネルは、枠が水色になります。メニューの下には、選んでいる画面で何ができるかが 1 行で表示されます。

色の意味はどの画面でも同じです。緑は成功、黄色は警告やそろっていない結果（partial、skipped、timeout、unsupported）、赤は失敗、水色はいま選んでいる項目やパネルを表します。partial や inconclusive の結果を緑で表示することはありません。80x24 のターミナルに収まるように作られており、収まらない内容は `↑` `↓` でスクロールできます。そのときはパネルの最下行に、どの行を表示しているかが出ます。

| 場所     | キー                   | 操作                                     |
| -------- | ---------------------- | ---------------------------------------- |
| メニュー | `↑` `↓` または `j` `k` | 画面を選ぶ                               |
| メニュー | `Enter` または `→`     | 画面に入る                               |
| メニュー | `1`〜`6`               | その画面を直接開く                       |
| メニュー | `?`                    | キーの説明を表示する・閉じる             |
| メニュー | `q`                    | 終了する                                 |
| どこでも | `Ctrl+C`               | 終了する                                 |
| 画面の中 | `↑` `↓` または `j` `k` | 一覧で移動する、テキストをスクロールする |
| 画面の中 | `Enter`                | 選ぶ                                     |
| 画面の中 | `Esc`                  | 戻る。画面の最初の階層ではメニューに戻る |

## 画面

### ホーム

4 枚のカードで、プロジェクトの状態をまとめて表示します。

- **Project**: プロジェクトのディレクトリ（ホームディレクトリは `~` で表示）、パッケージマネージャー、設定ファイル。
- **Latest run**: 最新の run の verdict、profile、何分前に実行したか、かかった時間、終了コード、各ステージとその結果の印（`✔` は成功、`!` は partial や unsupported、`✖` は失敗、タイムアウト、キャンセル）、重大度ごとの finding の数、run が記録した根拠。根拠は、テストの評価、mutant、プロパティベーステスト、ソルバーの claim を、それぞれ状態ごとに数えて示します。全体を 1 つの点数にまとめることはしません。この数そのものが結果です。
- **Next steps**: 次にすることと、それを行う画面のキー。たとえば最初の run を始めるなら `4`、finding を読むなら `2`、proposed の仕様をレビューするなら `3` です。ホームでそのキーを押すと、その画面に移ります。
- **Tools**: `veritas doctor` が報告する機能ごとの状態（enabled は `✔`、degraded は `!`、disabled は `✖`）と、足りないツールごとに、それで使えなくなる機能や制限される機能。

幅の広いターミナルでは、カードが 2 列に並びます。設定がまだないプロジェクトでは、`veritas init` と同じように、検出した設定で `.veritas/config.json` を作るかを確認します。

### 結果

run を新しい順に 1 行ずつ一覧します。各行には、色付きのラベルで示す verdict、finding の数、profile、何分前に実行したか、かかった時間が並びます。

run を選ぶと、その内容が開きます。上のカードに verdict、終了コード、policy の理由が出て、その下に各ステージとその印とかかった時間、重大度ごと・種類ごとの finding の数、finding の一覧が続きます。finding は重大度の高い順に並び、重大度は色付きで、`confirmed`（確認済み）か `suspected`（疑い）かも示します。`e` を押すと、finding の代わりに run の根拠の数が表示され、もう一度 `e` を押すと戻ります。

finding を選ぶと、報告した理由に続いて、根拠が見出しごとに表示されます。場所、引用した文を含む出典、Property、テストとその評価、mutant（生き残ったものが先）、ソルバーの claim です。内容は `veritas explain <finding-id>` が出す根拠と同じです。次の対応は最後に別の見出しで表示します。根拠ではなく提案だからです。長い finding は `↑` `↓` でスクロールできます。根拠のつながりは最新の run についてだけ保存されているので、それより古い run では、finding と根拠の ID を表示します。

### 仕様

Property を生成した最新の run の Property を一覧します。

| キー    | 場所     | 操作                                                                                     |
| ------- | -------- | ---------------------------------------------------------------------------------------- |
| `f`     | 一覧     | status で絞り込む（all、proposed、reviewed、accepted、rejected、conflicted、superseded） |
| `d`     | 一覧     | 前回の run からの変化を表示する（`veritas spec diff`）                                   |
| `Enter` | 一覧     | Property を表示する（対象、引用した文、衝突している Property、これまでの決定）           |
| `a`     | Property | 理由を入力して accept する                                                               |
| `r`     | Property | 理由を入力して reject する                                                               |

理由は必須で、空のときは何も記録しません。決定は `.veritas/approvals.json` に記録されます。actor は `VERITAS_ACTOR`、設定されていなければ git の `user.name` です。`veritas spec accept` と `veritas spec reject` と同じ形で記録されます。

### 実行

オプションを選んでから **Start** を選びます。

| オプション                      | 既定値           | 対応するオプション   |
| ------------------------------- | ---------------- | -------------------- |
| Profile                         | `quick`          | `--profile`          |
| Offline                         | yes              | `--offline`          |
| Include proposed specifications | no               | `--include-proposed` |
| Since                           | プロジェクト全体 | `--since <ref>`      |

実行中は、次のものが表示されます。

- 経過時間と、終わったステージの数を示す進捗バー
- profile のすべてのステージ。終わったものにはかかった時間、実行中のものには経過時間が付きます
- いま何が起きているかを流すログ。ステージの開始と終了とその結果、mutator・Z3・Vitest などのプロセスの開始と終了、mutator の出力、キャッシュの利用が流れます

新しいイベントが来なくてもスピナーと経過時間は動き続けるので、mutation テストのような長いステージでも止まっているようには見えません。`Esc` で実行をキャンセルします。

終わるとログは消え、verdict、終了コード、finding の数、全体の時間、ポリシーの理由、記録されたステージの一覧が表示されます。`Enter` で **結果** の画面を開き、finding を確認できます。

キャンセルすると **Run cancelled** と表示され、実行 ID と、記録されたステージの一覧が出ます（キャンセルで止まったステージはたいてい `cancelled` ですが、`error` と記録されることもあります）。キャンセルした実行の結果はそろっていないので、verdict は表示しません。`Enter` で **結果** の画面は開けます。キャンセルした実行は、その一覧のいちばん上にあります。失敗したときやキャンセルしたときは、どこで止まったかが分かるよう、ログの最後の数行が残ります。実行中に画面を離れたり TUI を終了したりした場合も、実行はキャンセルされます。

### テストの改善

**Create a plan** は `veritas improve` と同じで、accepted の仕様から期待値を取ったテストを提案します。プロジェクトのファイルは書き換えません。**Also use proposed specifications** をオンにすると、`--include-proposed` と同じく proposed の仕様も使います。

計画には、目標、提案するテスト、リスク、パッチが表示されます。適用できるものがあれば、`a` を押して `y` で確定します。TUI はその計画の承認トークンを使って、`veritas improve --apply --plan <id> --approve <token>` と同じように適用します。[計画の適用](/ja/guide/improving-tests)の検査はすべてそのまま行われます。テストは隔離したコピーで実行し、条件をすべて満たしたときだけ新しいテストファイルを書き込みます。CI では適用を拒否します。`Esc` で計画の作成や適用をキャンセルできます。

### 設定

すべての設定を、**Sources**、**Mutation testing**、**Policy** のようなセクションに分けて一覧します。ファイルに書かれていない設定も含みます。`Enter` でセクションを開閉します（`→` と `←` も使えます）。各設定には、読みやすい名前と値が並び、既定値と違う値には `changed` が付きます。セクションの行には、その中で変更されている設定と、保存していない設定の数が出ます。

カーソルのある設定は、一覧の下で説明します。何を決める設定か、いまの値、既定値、受け付ける値です。説明と既定値は設定のスキーマから取っており、[設定リファレンス](/ja/reference/configuration)と同じものです。

| キー    | 操作                                                                                                                                     |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `Enter` | 設定を変える。オンとオフの設定は切り替わり、選択肢の決まった設定は選択肢の一覧が、数値や文字列は入力欄が、リストはリストの編集画面が開く |
| `Space` | オンとオフを切り替える                                                                                                                   |
| `r`     | 既定値に戻す                                                                                                                             |
| `s`     | 保存していない変更を確認して保存する                                                                                                     |
| `Esc`   | 画面を離れる。保存していない変更があるときは、破棄してよいかを確認する                                                                   |

リストの編集画面では、`a` で項目を追加し、`Enter` で選んだ項目を変え、`d` で削除します。レポートの形式のように選択肢の決まったリストは、`Space` でチェックを付け外しします。

変更はそのたびに、`veritas` が設定ファイルを読み込むときと同じスキーマで検査します。数値の欄に文字を入れたときや、範囲外の数値を入れたときのように受け付けられない値は、その設定のところに赤で理由を表示し、何も変えません。変更はすぐには書き込みません。保存していない変更のある設定には `*` が付き、見出しに保存していない変更の数が出ます。`s` を押すと変更ごとに変更前と変更後の値が表示され、`y` を押したときだけ書き込みます。書き込むのは `.veritas/config.json` だけです。

ネットワークや LLM を使うようになる設定には、`network` または `LLM` の印が付きます。GitHub と Web の出典、LLM へ文書全体を送る設定、LLM のプロバイダー、codex のファイル読み取り、ネットワークを隔離できない環境でのプロジェクトのコードの実行です。設定がオンのときは印が強調され、説明にはオンにすると何が起きるかが書かれています。どれも既定ではオフです。オンにしていても、offline の run（実行の画面の既定）では、ネットワークの出典を読まず、LLM にも何も送りません。

`veritas.config.ts`、`.mjs`、`.js` で設定しているプロジェクトでは、読み込むとプロジェクトのコードが実行されるため、読み取り専用で表示します。TUI はこれらのファイルを読み込むことも書き込むこともしません。直接編集してください。
