# トラブルシューティング

前半はよくあるエラーとその対処です。後半で、実行の中身を調べる方法を紹介します。

## よくある問題

| 症状                                                                                       | 原因と対処                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `VITEST_NOT_FOUND`                                                                         | `init` が Vitest も Jest も見つけられませんでした。プロジェクトが使うランナーを入れてください（`npm install -D vitest` または `jest`）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `JEST_NOT_FOUND`                                                                           | 設定が Jest を指定している（`analysis.testFramework: "jest"`）のに、プロジェクトに Jest がありません。Jest を入れる（`npm install -D jest`）か、プロジェクトが使っているランナーを設定してください                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `init` が違うテストランナーを選んだ                                                        | `init` が Vitest と Jest の両方がインストールされている（または両方とも宣言だけの）状態を見つけ、どちらか判断できなかったため、Vitest を選んで次の手順でそのことを伝えています。設定ファイルがあるだけのランナーが、インストール済みのランナーより優先されることはありません。`.veritas/config.json` の `analysis.testFramework` を書き換えるか、ターミナルで `init` を実行して質問に答えてください                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `CONFIG_MISSING`                                                                           | `.veritas/config.json` がありません。`veritas init --yes` を実行し、CI 用にファイルをコミットしてください                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `NO_RUN`                                                                                   | `spec`、`report`、`explain`、`improve` は最新の実行を読みます。先に `veritas run` を実行してください                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `doctor` で `mutate` が disabled                                                           | テストランナーが入っていません。プロジェクトの依存をインストールしてください。mutation テストには Vitest 4 以降（または Jest 30）と、`node_modules` へのインストール（Yarn Plug'n'Play ではないこと）も必要です                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `doctor` で `mutator` が `degraded`、mutation の結果に `experimental` の警告が付く         | @mizchi/mutator 自身が Jest への対応を実験的としているためです。mutation は実行しますが、別の入力が必要な抜けは「検出されない」と報告されます（Jest には weak mutation がありません）。失敗の原因がテストではなく連携にあることもあるので、意外な結果は自分のテスト実行で確かめてください                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Jest で mutation のステージが `unsupported`                                                | mutator が Jest で実行できるのは、ネイティブ ESM のプロジェクト（package.json に `"type": "module"`）で Jest 30 を使い、Jest の `projects` を使っていない場合だけです。メッセージに理由が出ます。ほかのステージはそのまま実行します                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Veritas や mutator のもとでだけ Jest のテストが失敗する                                    | Veritas と mutator は、ネイティブ ESM に必要な `node --experimental-vm-modules` を付けて Jest を起動します。Babel や ts-jest で CommonJS として Jest を動かしているプロジェクトでは挙動が変わることがあります。失敗のメッセージで原因を確かめてください                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| mutation のステージが `failed`                                                             | mutant がなくてもテストが失敗しています。先にテストを通してください。自分のテストコマンドでは通る場合は、メッセージの `first error` の行を確かめてください。Veritas に同梱の `@mizchi/mutator` は、プロジェクトのテストランナーでテストを実行しますが、自分のファイルの一部を Veritas のインストール先から読み込みます。エラーにそのファイルが出ている場合は、`@mizchi/mutator` をプロジェクトの devDependencies に追加してください                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| mutation のステージが `error` で `instrumentation failed` と出る                           | mutator は mutant を切り替えられるように、各ソースファイルを書き換え（計装し）ます。メッセージに出ているファイルの計装後のコードを、プロジェクトのバンドラ（Vite）が解析できませんでした。そのファイルが自分のテスト実行では読み込める場合は、たいていバンドラのパーサのバグです（Vite 8 が rolldown を通して使う oxc の一部のバージョンなど）。Vite（または rolldown）を更新すれば、たいてい直ります。mutator が `--exclude` に対応していれば、Veritas はそのファイルを外して、`mutation.timeoutMs` の残り時間の範囲で mutator をもう一度だけ実行します。ファイルが 5 つを超えるときや、残り時間が足りないときは実行しません。`mutation.timeoutMs` を増やすか、`--since` で範囲を絞ってください。2 回目も同じ解析エラーで失敗したときは、計装しなくてもそのファイルを解析できないということです。原因はソースコードかプロジェクトのツールチェーンにあり、ステージは `failed` になります |
| `left out of mutation` の警告が出て、mutate のステージが `partial` になる                  | 警告に出ているファイルは計装後のコードを解析できなかったので（上の行を参照）、外して mutator を実行しました。そのファイルの mutant は実行していないため、ステージは `partial` になり、実行結果は `pass` になりません。Vite（または rolldown）を更新して、もう一度実行してください                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| mutation のステージが `timeout` で `no mutant had finished` と出る                         | mutator はベースライン（mutant なしでのテストの実行）を終えましたが、どの mutant も終わらないうちに `mutation.timeoutMs` に達して停止されました。mutator の時間予算（Veritas は `mutation.timeoutMs` の 75% に設定します）は新しい mutant を始めるかどうかにしか効かないので、実行を時間内に終わらせることはできません。メッセージに、mutator が実行する mutant の計画をまだ出力していなかったと書かれている場合は、mutator が mutant を実行する前に行う型チェックに時間がかかっている可能性が高いです。`mutation.typecheck` を `"off"` にすると型チェックを省けます。そうでない場合は、mutant の実行そのものに時間がかかっています。どちらの場合も、`--since <ref>` や `mutate --scope <path>` で範囲を絞るか、`mutation.timeoutMs` を増やすと改善します。型チェックを省くと、コンパイラが受け付けない mutant も実行して数えます。そのことはステージのメッセージに表示されます          |
| `time budget ... ran out` の警告が出て、mutate のステージが `partial` になる               | mutator が時間予算（`mutation.timeoutMs` の 75%。2 回目の実行では残り時間の 75%）を使い切ったので、新しい mutant を始めるのをやめ、実行した分だけでレポートを書きました。実行しなかった mutant の数は警告に出ています。それらは `pending` のまま残るため、`--since` を付けていてもステージは `partial` になり、実行は `pass` になりません。`--since <ref>` や `mutate --scope <path>` で範囲を絞るか、`mutation.timeoutMs` を増やしてください。このような結果はキャッシュしません                                                                                                                                                                                                                                                                                                                                                                                                        |
| mutate のステージに `check of N test(s) static analysis could not link ... skipped` と出る | メインの mutation の実行のあとに `mutation.timeoutMs` が 30 秒も残らなかったので、静的解析がプロジェクトのコードと結びつけられなかったテストの確認を行いませんでした。それらのテストは静的解析だけで報告されます。`--since <ref>` や `mutate --scope <path>` でメインの実行の範囲を絞るか、`mutation.timeoutMs` を増やしてください。型チェックに時間がかかっているなら `mutation.typecheck` を `"off"` にします。確認の実行が自分の時間予算を使い切ったときも、一部のテストは同じように確かめられないまま残ります。ステージのメッセージでは、mutant を 1 つも実行しなかったテストとして数えます                                                                                                                                                                                                                                                                                          |
| `doctor` で `sandbox` が `unavailable`                                                     | Node.js 25 未満では、プロジェクトのコードのネットワークアクセスを遮断できません。Node.js 25 以上を入れるか、`VERITAS_SANDBOX_NODE` で指定してください。`sandbox.allowNetworkWithoutIsolation` を設定すると遮断せずに実行します                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `semantic_mismatch`                                                                        | 整数モデルと JavaScript の結果が違います（安全な整数を超える値など）。`formal.integerDomain` を狭めるか、その関数はテストで確かめてください                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 結果が `unsupported`                                                                       | 関数が形式検証の対応範囲の外のコードを使っています。[対応環境](/ja/concepts/support-matrix)を参照してください                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

| メモリ不足で `error`                                                                       | `limits.memoryMb`（既定 2048 MiB）を増やしてください。プロジェクトのコード、テストランナー、mutator、Z3 に適用されます                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `doctor` で Lean が `unavailable`                                                          | elan で Lean 4 を入れてください。`doctor` は `~/.elan/bin` も探します                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

| `IMPROVE_UNSAFE_LINK`                                                                      | プロジェクトの外を指すシンボリックリンクがあります。実際のファイルやディレクトリに置き換えてください                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |

## 実行の中身を調べる

| 手段                                 | 分かること                                                                                                                                                                                                                       |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--debug` または `VERITAS_DEBUG=1`   | 標準エラー出力にデバッグのイベントが出ます。子プロセス（コマンド、引数、作業ディレクトリ、所要時間、終了コード、タイムアウトや強制終了）、プロジェクトのコードの制限つき呼び出し、ステージの開始と終了、キャッシュのヒットとミス |
| `--log-format json`                  | 標準エラー出力のログを、一行一つの JSON オブジェクトにします。標準出力は変わらないので、`--json` の出力は JSON だけのままです                                                                                                    |
| `.veritas/runs/<run-id>/trace.jsonl` | 同じイベントを、デバッグレベルも含めて実行ごとに記録します。上限は 4 MB で、最後の行に捨てたイベントの数が出ます                                                                                                                 |
| `veritas replay <run-id>`            | 以前の実行を、記録したステージとオプションでもう一度実行します                                                                                                                                                                   |
| `veritas report --run <run-id>`      | 指定した実行のレポート                                                                                                                                                                                                           |

ログとトレースには、環境変数の値もファイルの中身も含まれず、伏せ字の処理を通しています。

```bash
veritas --debug --log-format json run --profile standard 2> veritas-log.jsonl
```

`trace.jsonl` は一行が一つのイベントです。

```text
{"event":"stage","stage":"discover","at":"start","time":"2026-11-20T10:55:31.938Z","level":"debug","message":"stage discover started"}
```

`replay` は、どの実行を繰り返すかを表示してから実行します。

```text
replaying prove from run-20261120T105508829Z-000-017911 (prove --include-proposed)
```

ここにない問題は、`veritas doctor --json` の出力と `trace.jsonl` の関係する部分を添えて、[GitHub](https://github.com/under18dev/veritas/issues) に Issue を作成してください。
