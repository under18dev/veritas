# セキュリティモデル

リポジトリの内容、Web ページ、モデルの出力はデータとして扱い、指示としては扱いません。ネットワークへのアクセスは既定でオフで、明示的な承認なしにプロジェクトのファイルを変えることもありません。プロジェクトのコードは信頼するコードとして扱うので、信頼できないリポジトリは隔離した環境で分析してください（[信頼できないリポジトリ](/ja/guide/untrusted-repositories)）。以下では、Veritas が守るもの、信頼しないものとして扱う入力、脅威ごとの対策を挙げます。

## 守るもの

利用者のソースツリーと git の状態、環境にある認証情報（API キー、`GITHUB_TOKEN`）、CI の秘密情報、そして Veritas が出す主張の正しさです。

## 信頼しない入力

リポジトリの内容（コード、ドキュメント、テスト、設定）、Issue とプルリクエスト、Web ページ、LLM の出力、mutation とソルバーの出力、フォークからのプルリクエストです。

## 対象外

分析するプロジェクトに含まれる悪意のあるコードは対象外です。プロジェクトのコードを実行する手順（property-based テスト、反例の再生、mutation の実行、`improve`）は上に書いたとおり制限していますが、Veritas は悪意のあるコードに対するセキュリティのサンドボックスではありません。Node.js のパーミッションモデルが防ぐのは事故であって、攻撃ではありません（[ADR 0011](/adr/0011-trusted-project-code)、英語）。信頼できないリポジトリは、ネットワークのないコンテナーのような隔離した環境の中で Veritas を使って分析してください（[信頼できないリポジトリ](/ja/guide/untrusted-repositories)を参照）。
