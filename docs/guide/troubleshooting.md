# Troubleshooting

Common errors and their fixes come first. After them are the tools for finding out what a run did.

## Common problems

| Symptom                                                                                   | Cause and fix                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `VITEST_NOT_FOUND`                                                                        | `init` found neither Vitest nor Jest. Install the runner the project uses (`npm install -D vitest`, or `jest`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `JEST_NOT_FOUND`                                                                          | The configuration names Jest (`analysis.testFramework: "jest"`) but the project does not have it. Install it (`npm install -D jest`), or set the runner the project uses                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `init` chose the wrong test runner                                                        | `init` found both Vitest and Jest installed (or both only declared) and nothing told them apart, so it chose Vitest and said so in its next steps. A runner that is only configured never wins over an installed one. Set `analysis.testFramework` in `.veritas/config.json`, or run `init` in a terminal, where it asks                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `CONFIG_MISSING`                                                                          | No `.veritas/config.json`. Run `veritas init --yes`, and commit the file for CI                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `NO_RUN`                                                                                  | `spec`, `report`, `explain` and `improve` read the latest run. Run `veritas run` first                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `mutate` disabled in `doctor`                                                             | The test runner is not installed: install the project's dependencies. Mutation testing also needs Vitest 4 or later (or Jest 30), and `node_modules` (not Yarn Plug'n'Play)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `mutator` is `degraded` in `doctor`, and mutation results carry an `experimental` warning | @mizchi/mutator marks its Jest support as experimental. Mutation still runs, but a gap that needs another input is reported as not detected (Jest has no weak mutation), and failures may come from the integration rather than your tests. Check surprising results with your own test run                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Mutation stage `unsupported` with Jest                                                    | mutator runs Jest only in native ESM projects (`"type": "module"` in package.json), with Jest 30, and not with Jest `projects`. The message names the reason. The other stages still run                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Jest tests fail only under Veritas or mutator                                             | Veritas and mutator start Jest with `node --experimental-vm-modules`, as native ESM needs. A project that runs Jest through Babel or ts-jest in CommonJS may behave differently there; the failing message says how                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Mutation stage `failed`                                                                   | Your tests fail without any mutant. Make them pass first. If they pass with your own test command, read the `first error` line of the message. The copy of `@mizchi/mutator` bundled with Veritas runs your project's test runner, but loads some of its own files from where Veritas is installed. If the error names such a file, add `@mizchi/mutator` to the project's devDependencies                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Mutation stage `failed` with `no test ran`                                                | mutator ran no test, so every mutant would have read as not covered. The `include` and `exclude` patterns of your Vitest config, or of its projects, match none of the test files Veritas selected (the message names them). Check those patterns against the test files, and `analysis.testInclude` against the files your config runs                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Mutation stage `failed` with `cannot limit the Vitest project` or `runs none of them`     | Veritas runs only the selected test files, in the projects of your Vitest config whose patterns match them. It stops instead of running other tests when a project cannot be limited (it declares projects of its own, or its config cannot be loaded with the project's Vite) or when no project matches any selected file. The message names the project or the reason                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Mutation stage `error` with `instrumentation failed`                                      | mutator rewrites (instruments) each source file so it can switch mutants on and off, and the project's bundler (Vite) could not parse the instrumented copy of the file the message names. If the file loads in your own test run, this is usually a parser bug in the bundler, such as the one in the oxc version that Vite 8 uses through rolldown, and upgrading Vite (or rolldown) usually fixes it. When mutator supports `--exclude`, Veritas runs it once more without that file, within what is left of `mutation.timeoutMs`. It does not run again when more than 5 files are named or too little time is left; raise `mutation.timeoutMs` or narrow the run with `--since`. If the second run fails with the same parse error, the file does not parse even without instrumentation: the source or the project's toolchain is at fault, and the stage is `failed` |
| `left out of mutation` warning, mutate stage `partial`                                    | The instrumented copy of the files the warning names did not parse (see the row above), so mutator ran without them. Their mutants were not run, so the stage is `partial` and the run cannot `pass`. Upgrade Vite (or rolldown) and run again                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Mutation stage `timeout` with `no mutant had finished`                                    | mutator finished the baseline (your tests without any mutant) but reached `mutation.timeoutMs` and was stopped before any mutant had finished. Its time budget, which Veritas sets to 75% of `mutation.timeoutMs`, only keeps it from starting new mutants, so it does not end the run in time. When the message says mutator had not printed its plan of mutants to run, the time most likely went to type-checking the mutants, which mutator does before running them: set `mutation.typecheck` to `"off"` to skip that step. Otherwise the mutants themselves are slow. In both cases, narrowing the run with `--since <ref>` or `mutate --scope <path>`, or raising `mutation.timeoutMs`, helps. Without type-checking, mutants the compiler would reject are run and counted too, and the stage messages say so                                                       |
| `time budget ... ran out` warning, mutate stage `partial`                                 | mutator used up its time budget (75% of `mutation.timeoutMs`, or of what was left of it when mutator ran a second time), stopped starting new mutants and wrote its report for the ones it had run. The warning gives the number it did not run. Those stay `pending`, so the stage is `partial` and the run cannot `pass`, also with `--since`. Narrow the run with `--since <ref>` or `mutate --scope <path>`, or raise `mutation.timeoutMs`. Results like these are not cached                                                                                                                                                                                                                                                                                                                                                                                           |
| `check of N test(s) static analysis could not link ... skipped` in the mutate stage       | The main mutation run left less than 30 seconds of `mutation.timeoutMs`, so the check of the tests static analysis could not link to project code did not run, and those tests are reported from static analysis alone. Narrow the main run with `--since <ref>` or `mutate --scope <path>`, raise `mutation.timeoutMs`, or set `mutation.typecheck` to `"off"` when type-checking takes the time. A check that ran out of its own time budget leaves some tests unchecked in the same way; the stage messages count them as having run no mutant                                                                                                                                                                                                                                                                                                                           |
| `sandbox` is `unavailable` in `doctor`                                                    | Node.js below 25 cannot block network access from project code. Install Node.js 25 or later, or point `VERITAS_SANDBOX_NODE` at one. `sandbox.allowNetworkWithoutIsolation` runs the code without blocking                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `semantic_mismatch`                                                                       | The integer model and JavaScript disagree, for example on values beyond safe integers. Narrow `formal.integerDomain`, or cover the function with tests                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `unsupported` claims                                                                      | The function uses code outside the formal subset; see the [support matrix](/concepts/support-matrix)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `timeout` claims                                                                          | The solver hit its time limit. Raise `formal.maxSolverMs` or narrow `formal.integerDomain`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `error` from running out of memory                                                        | Raise `limits.memoryMb` (default 2048 MiB). It applies to project code, the test runner, mutator and Z3                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Lean is `unavailable` in `doctor`                                                         | Install Lean 4 with elan. `doctor` also looks in `~/.elan/bin`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `PROPERTY_NOT_FOUND`, or an accepted property is `proposed` again                         | The file containing the statement changed, so the property has a new ID. Run `veritas spec diff` and review the new property                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `APPROVAL_MISMATCH`                                                                       | The token does not belong to the plan, or the plan changed. Run `veritas improve --dry-run` again and use the new token                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `IMPROVE_APPLY_IN_CI`                                                                     | `--apply` is refused in CI. Apply locally                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `IMPROVE_UNSAFE_LINK`                                                                     | The project contains symbolic links pointing outside it. Replace them with real files or directories                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| A documented rule does not appear in `spec list`                                          | The rules read threshold phrases only; other statements stay unmapped. An [LLM provider](/guide/llm-providers) can read some of them as proposed properties                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |

## See what a run did

| Tool                                 | What it shows                                                                                                                                                                                           |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--debug` or `VERITAS_DEBUG=1`       | Debug events on stderr: every child process (command, arguments, working directory, duration, exit code, timeout or kill), restricted calls of project code, stage start and end, cache hits and misses |
| `--log-format json`                  | The stderr log as one JSON object per line. stdout is unchanged, so `--json` output stays pure JSON                                                                                                     |
| `.veritas/runs/<run-id>/trace.jsonl` | The same events, debug level included, for every run; at most 4 MB, with a final line counting dropped events                                                                                           |
| `veritas replay <run-id>`            | Runs a previous run again with its recorded stages and options                                                                                                                                          |
| `veritas report --run <run-id>`      | The report of a specific run                                                                                                                                                                            |

Logs and traces contain no environment values or file contents, and are redacted.

```bash
veritas --debug --log-format json run --profile standard 2> veritas-log.jsonl
```

Each line of `trace.jsonl` is one event:

```text
{"event":"stage","stage":"discover","at":"start","time":"2026-11-20T10:55:31.938Z","level":"debug","message":"stage discover started"}
```

`replay` names the run it repeats before running it:

```text
replaying prove from run-20261120T105508829Z-000-017911 (prove --include-proposed)
```

If your problem is not listed here, open an issue on [GitHub](https://github.com/under18dev/veritas/issues) with the output of `veritas doctor --json` and the relevant part of `trace.jsonl`.
